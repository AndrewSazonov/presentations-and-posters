Answers to the questions this talk usually gets.

Why Qt and QML

A declarative UI language a screen is described as layout and state; a prototype needs little imperative code, which is not the same as "no code"

Live Preview an edit reaches the running application without a rebuild

One source, three platforms macOS, Windows and Linux, with nothing for the user to install first

A clean line between screens and science the frontend talks to a Python backend; either side can be replaced

The honest caveat for "why not the web?": a desktop application was the right answer for a tool that reads local files and runs a fit on the user's own machine. A browser frontend is a separate discussion, not a correction of this one.

The UX Expert Review

Phase 1 · use and document meet the design the way a new user meets it, write down what goes wrong

Phase 2 · review and root causes every component, seen through each design driver in turn — seven views of one screen

Phase 3 · report and co-create findings grouped by screen: a problem, a root cause, a proposed fix

Design Psychology, UX Expert Review, v3, January 2023.

Three toolboxes

① Move it to the basic level what do users see before they read? space, orientation, movement, amount and size — inspected with the blur filter

② Move it to the skills level what does this user already know? does the design match their mental model and the conventions of their field?

③ Remove it optimise and simplify, stay consistent and congruent, and put the information on the screen instead of in the user's head

Same source. "Recognition rather than recall" is the short version of ③.

The review reply, in full

Every tab is a file you can read

The project is a folder, not a blob Project, Model, Experiment and Analysis each have their own file

The format is CIF, the one the field already uses named tags rather than cryptic labels — the file says what it means

Text mode shows that file inside the application nothing about the project is hidden behind the interface

A UX decision, not a storage decision: the user can check the program's work without learning a private format.

Diffraction analysis software

Programs FullProf Suite · Jana2020 · GSAS-II · SHELX · MAUD · FOX · Mag2Pol · CrysPy Editor · TOPAS · TOPAS-Academic · Materials Studio Reflex · HighScore

Libraries CrysFML · CCSL · pyobjcryst (ObjCryst++) · CCTBX · CrysPy · GSAS-II

EasyDiffraction does not replace these. It puts one interface, and one project format, in front of them.

Not cross-platform

Jana2006 / 2020 · Windows only

Input files written for the program

FullProf PCR · cryptic labels, values by position

What else is shared

Organisation-level architecture decision records

One project template (Copier) across every repository

One set of code-quality rules (Ruff) for linting and formatting

CI/CD for code and packages (GitHub Actions)

Automated releases and documentation (PyPI, MkDocs)

The interface is the visible part of the reuse. This is the rest of it.

We designed the workflow first, and let the screens follow it

Then we made the result a module, so the next technique inherits it
