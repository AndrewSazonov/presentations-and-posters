One workflow, so one interface.

This is the slide that earns the next section. Designing for the WORKFLOW rather than for one technique's code is what left us with an interface that any technique sharing that workflow can wear — which is the whole unification claim, and the talk's title. The left panel dims on the second click on purpose: the point is not that the usual order is wrong, it is that it is the one everybody else is still in. Say the two arrows out loud. The mechanism, if anyone asks, is in the backup deck: QML describes a screen as layout and state rather than drawing it, the frontend meets a Python backend at a thin boundary so the science can be stubbed or arrive late, and Live Preview puts an edit into the running application without a rebuild. None of that is the point on this slide — the point is the ORDER, and what it costs to change your mind. Do not call QML "no-code": it is a declarative UI language, which is not the same claim.
