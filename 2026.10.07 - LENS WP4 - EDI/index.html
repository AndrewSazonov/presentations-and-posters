Reusing crystallographic libraries,

Andrew Sazonov
ESS DMSC

LENS WP4 · 7 October 2026

Two routes to the same goal. EasyDiffraction puts one interface on top of existing crystallographic libraries; crysta is the in-house engine, new this year, written to find out how far the calculation itself can be pushed. The talk follows that order.

Hard to start, and missing what new instruments need

The first three are about getting started: everything on screen at once, input files written for the program rather than for people, and extra software to install before anything runs. Then the row slides on, and the problems stop being about comfort: Jana runs on Windows only, site susceptibility for MAGIC exists only in CrysPy and CCSL, and 2D Rietveld for DREAM only in a modified GSAS-II. Say again that the science in all of these is excellent.

Libraries

CrysFMLCCSLCCTBXpyobjcrystCrysPyPDFfit2…

Each library brings what it does best — written and validated by its own experts

Instead of a new engine, the first route was to rely on what already exists. Out of the field we picked libraries, not programs, and each for what it does that the others do not: CrysFML for symmetry and magnetic structures, CrysPy for polarised neutrons and site susceptibility (needed for MAGIC), PDFfit2 for the pair distribution function. The physics stays with the people who wrote and validated it.
