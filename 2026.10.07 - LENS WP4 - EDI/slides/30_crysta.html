The experiment

A pilot project: how far can AI-supported development
take a high-performance crystallographic library?

So we started a pilot project to test the limits: a new crystallographic calculation and refinement library, written in C++ for speed, with AI writing the code and a human owning the requirements, the references and the verdict on what is correct. The existing libraries stay essential: they are the independent references every result is checked against.

Machine · VISA, an Intel Xeon node · 6 cores every timing on a single thread

Everything in this section is one case: the WISH banks 2 and 9 time-of-flight pattern of the NCAF standard, refined from one declared start with the same 48 free parameters in every engine, on a VISA node (the facility’s remote analysis service; Intel Xeon Cascadelake with AVX-512, 32 GB, Ubuntu 22.04). The box has 64 cores, but every figure in this talk uses 1 or 6 threads — the 64-thread rows are in the backup. FullProf is the reference. Say this once here and the shorthand on the charts is readable.

crysta .github/workflows/ci.yml: -Werror, clang-tidy, cppcheck, clang-format, ASan+UBSan build, ruff (the EasyDiffraction "as strict as possible" rule set, pyproject.toml), mypy strict = true, coverage gates cpp_lines_min = 80 and python_surface_min = 80, byte-identity gates for SIMD width, thread count and link-time optimisation. The active workflow uses Linux and macOS. Some checks run on merge, and documentation changes can use a shorter path. A written merge rule does not itself establish a technical restriction.
