The approach of the first half works, but wrappers around several libraries and numerical derivatives are not fast.

A pilot project

A pilot project

Can AI-supported development build a fast crystallographic library?

So we started a pilot project to test the limits: a new crystallographic calculation and refinement library, in C++ for speed, with AI writing the code and a human owning the requirements, the references and the verdict on what is correct. The existing libraries stay essential: every result is checked against them.

crysta

crysta
Eigen · nanobind · CMake

crysta

crysta
C++ → Python

A fourth calculation engine, built in-house.

crysta is a C++ crystallographic calculation and refinement engine with Python bindings: Eigen for the linear algebra, nanobind for the bindings, CMake to build it. It does not replace the picture from before; it slots into it, as one more calculation engine under the same EasyDiffraction interface.

One real case, the same for every engine.

Everything that follows is this one case: the WISH banks 2 and 9 time-of-flight pattern of the NCAF standard, refined from one declared start with the same 48 free parameters in every engine. FullProf is the reference. The machine is a VISA node, one thread for every timing.

Every bar is one thread. crysta’s bar is its measured refinement time multiplied by three, so the comparison uses a slower descent strategy than its fastest. CrysPy through EasyDiffraction 468 s, CrysPy direct 329 s, FullProf 13 s, crysta about 3 s. FullProf is step-efficient because it also uses analytic derivatives; crysta gets them automatically.
