1.6Earlier EasyDiffraction

What each library brings

CrysFMLmature, wide coverage · Fortran

CrysPymore polarised-neutron options · Python

PDFfit2pair distribution function · C++

Different libraries for different analysis methods.

code.ill.fr/scientific-software/crysfml · cryspy.fr · diffpy.org. CrysFML is the most mature, with the widest coverage (symmetry, magnetic structures), CrysPy has more polarised-neutron options and site susceptibility (needed for MAGIC), PDFfit2 the pair distribution function. Each library is maintained by its own experts; EasyDiffraction gives them one interface.

1.7Earlier EasyDiffraction

Earlier software stack

Calculations come from the libraries; the interface is ours.

EasyDiffraction as the worked example — the same three layers hold for the other techniques, with different engines in the bottom row. Say that, or the room hears a claim about diffraction only. The order of the clicks is the argument: the bottom row was already there, written and maintained mostly by other people (CrysPy partly by us). The library above it is the one layer we wrote, so a scientist gets the same objects whichever engine does the arithmetic. Everything above that line is where the design effort actually went. The two outlines that follow say what ships where. The EasyDiffraction library is only our part: the Python API and its Python face; the engines are separate packages it uses. The application bundles everything: its GUI, the library and every engine. Explain the integration trade-off respectfully: reuse validated physics, but adapt differing data models, parameter conventions and fitting behaviour. The new product still uses third-party libraries; it is not dependency-free.
