The technical column is real but solvable. The organisational column is the one that decides whether anything gets shared, and none of it is a GUI problem. Worth saying plainly at a controls-heavy workshop: when this talk says "we", it means the Science Division.

Cut from the slide, still worth saying. UI GENERATION: the types essreduce declares are exactly what a generator would read; the notebooks we already have are the pattern; the same approach would work for the EasyScience libraries from their analysis notebooks, and a new project could be built this way from the start. Nothing here is running — the point is that the declarative half is already solved for other reasons, so the generator is a smaller job than it sounds. AI: built-in heuristics take over when there is no API key; it reaches the fitting engine over MCP, read-only, which is the design decision worth defending — a scientist has to be able to say where every number in a published refinement came from. Next is the same idea inside the EasyScience GUIs, starting with explaining a fit. AI coding assistants are routine in development; the only one we ship is this one.
